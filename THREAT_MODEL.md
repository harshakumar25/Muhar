# Muhar threat model (design draft)

Scope: a low-stakes, one-centre, one-session digital mock using synthetic questions. This model is a prerequisite for, not a certification of, a live exam. The public evidence protocol is distinct from the private question-bank and centre systems.

Iteration 3 adds a first synthetic confidentiality experiment described in [SEALED_PAPER_ARCHITECTURE.md](SEALED_PAPER_ARCHITECTURE.md) and mandatory deployment gates in [PROPOSAL.md](PROPOSAL.md). Test two different claims: access to the assembled form **before first authorised plaintext release**, and advance exposure to a later candidate **after another endpoint has opened it**. Hardware isolation targets the former. Corrupt centres, admission timing, repeated items and shift policy can still defeat the latter. No national fraud-prevalence estimate or CBT capacity claim follows from these tests.

## Assets and boundaries

| Asset | Must remain private until policy allows | Publicly checkable claim |
| --- | --- | --- |
| Question packages and separate answer keys | Yes | Selected questions match prior salted commitments after opening; answer keys follow a later policy |
| Eligibility metadata and draw rules | May remain committed until exam ends | The disclosed inventory/rules match the pre-round manifest |
| Beacon round and seed | Round fixed in advance; seed public after round | Authenticated future randomness was used |
| Exam manifest and public events | No | Complete leaves recompute to named witnessed roots, the full scan finds one authorised session freeze, and later policy events remain visible; the shadow Ethereum anchor agrees with the pre-seed prefix when present |
| Release keys and centre secrets | Yes | Authorized release attestations, not the secrets themselves |
| Candidate records and grievances | Yes | No personal data is needed for a public proof |

Trust boundaries: author/reviewer to bank; bank/auditor to signed manifest; operator to public log; log to **two consistency witnesses and a separate full-scan content monitor**; witnessed pre-seed checkpoint to Ethereum in the experimental arm; beacon to draw; operator/keyholders to centre; centre to candidate; private incident evidence to official investigator. A signature proves which key signed a statement, not that the physical statement is true. The mock's 2-of-2 witness quorum and monitor check are declared in its charter; witness cosignatures alone contain no content verdict. [C2SP's witness protocol](https://c2sp.org/tlog-witness@main) defines the consistency check.

## Attacks, defenses, and remaining limits

| Attacker goal | Required control or evidence | Residual limit |
| --- | --- | --- |
| Leak a question during authoring/review | Least-privilege bank access, per-item compartments, conflict declarations, access logs, controlled review rooms | An authorized author can remember or disclose their own item |
| Reconstruct the entire form despite closed release keys | Audit historical/cumulative access and overlapping assignments; prohibit routine whole-bank export; test both complete-bank and partial-bank knowledge covering all selected items | Full-bank access is sufficient but not necessary; an actor knowing every selected item and enough order metadata can reconstruct it. Encryption cannot revoke knowledge; any selection constraint must be committed before the seed |
| Read selected plaintext from assembly memory or diagnostic output | Approved attested assembly, recipient-bound key delivery, no preview/export API, restricted egress, bounded status, tested log/crash/backup paths | Ordinary-host assembly exposes memory to a privileged administrator; TEE hardware, firmware, application and side-channel assumptions remain |
| Bypass approvals by changing key policy, image allowlist, recovery settings or a root account | Independently governed changes, full principal/override inventory, deny direct decrypt outside approved attested context, controlled recovery | A superadministrator who can unilaterally override policy is a trusted actor, not protected against by an approval UI |
| Replay a release permit or substitute a recipient | Bind institution/exam/session, manifest/form, device key, current epoch, nonce, policy version and authenticated release interval; independently retained current state prevents rollback | Hardware attestation identifies an environment, not benevolent code or honest recipients; platform freshness must be implemented |
| Mislabel approval quorum as cryptographic threshold security | State two-of-three signed permits as application authorization; require a separately reviewed construction for distributed-key computation | Reconstructing shared keys in ordinary memory exposes them; multiple signatures alone do not make decryption cryptographically distributed |
| Stuff the bank with favoured/duplicate items or false tags | Independent confidential bank/blueprint review, duplicate checks, signed inventory, post-exam audit | A root proves commitment, not academic quality or impartiality |
| Present a counterfeit self-signed exam as official | Publish the institution's signing root, named log, and witness keys through an independently authenticated schedule; in an Ethereum-required profile, pin its registry code hash too | A fake site or compromised institutional root can still mislead users |
| Cancel after seeing an unfavourable seed and draw again | Independent post-seed cancellation quorum, public linked attempt history, incident evidence and review | Colluding decision makers can still abuse emergency authority |
| Choose the seed after seeing the bank | Freeze the exact future beacon round and rules in one named log checkpoint retained by both witnesses before the round; an independent monitor scans all leaves through that root and size. The shadow arm separately tests a public anchor. | Witness timing and clock trust, beacon committee assumptions, and outages still matter. A transaction included pre-round but finalized later does not establish pre-round finality. |
| Swap the bank, algorithm, paper, or render after freeze | Canonical/versioned commitments, exact replay, selected-item proofs, signed output artifact hash | Public replay needs enough metadata disclosure; otherwise an auditor must check |
| Deliver a different paper than the verified draw | Verifier compares the actual package's complete ordered content with selected item openings; CBT import/start rejects digest mismatch; operator and centre sign private digest receipts; participants retain signed exit receipts | A dishonest centre can still misstate display unless a participant or inspector retains evidence |
| Let a CBT platform reshuffle or change a language/asset after Muhar signs | Disable hidden reshuffling in the first mock; verify imported package and candidate variant, bind digest/variant in private session records | A compromised frontend can still render different pixels |
| Identify a selected form from its public digest before later shifts | Log a random-salted commitment to the package digest, reveal bare digest and centre receipts only after affected sessions | Candidates or insiders who have seen the form can still disclose it |
| Show different logs to different people | Append-only inclusion/consistency, 2-of-2 independently retained same-checkpoint cosignatures, complete-leaf mirrors, a full-scan content monitor, and one research-only Ethereum pre-seed checkpoint anchor | Without contemporaneous independent retention, active monitoring, and full leaves, detection can be delayed or impossible; the anchor cannot restore missing leaves or protect post-seed exceptions |
| Hide a second valid freeze behind a correct index or witness signature | For v0, download every leaf through named pre-seed and later checkpoints, recompute roots, check authorized signatures, and count freezes for the official session; reject two | A count covers only the complete inspected prefix of the named log, not unadvertised external documents or future events |
| Obtain the selected paper between seed and start | Precommit the draw and handoff schedule, measure the selected-form exposure interval in both mock profiles, restrict bank access, and review later threshold-controlled release and centre custody | The `T−60m` handoff simulation needs an earlier seed while admission may remain open; any full-bank insider can derive selected items once seed is public, and in-room communication persists |
| Compromise a centre computer or replace a binary | External signed-release verification, controlled boot/install, device checks, network isolation, two-person custody, drills | A compromised endpoint or dishonest officials can still copy content; self-hashing is ineffective |
| Force an outage to trigger an easy fallback | Precommitted retry/cancel policy, multiple beacon relays, mirrored log, rehearsed postpone process | Continuity may require postponement; no silent operator-selected seed |
| Abuse emergency authority | Named signers, quorum, signed reasons, append-only cancellation/reschedule, after-action review | Governance can be captured or colluding signers can lie |
| Ignore a valid candidate challenge or disclose proof after the remedy window | Publish a distinct procedural-integrity case type, durable receipt, evidence-preservation rule, proof-disclosure deadline, response owner, and appeal/remedy path; give a genuinely independent reviewer timely restricted access when public openings must wait; log a redacted resolution | A late public proof has retrospective value but may give a candidate no actionable remedy; Muhar cannot grant one itself |
| Make independent oversight nominal | Disclose auditor and witness appointment, funding, conflicts, rotation, and replacement rules | Operator-funded parties may still be dependent or collude |
| Identify a candidate or expose evidence | No candidate data or raw reports on chain; encrypted restricted evidence; retention and access policy | Small-group metadata and timing can still reveal information; review every public field |
| Poison open-source code or release | Protected branches, two independent reviewers for sensitive paths, dependency pinning, signed provenance, external artifact verification | A maintainer or build-platform compromise is still possible |
| Misattribute a leak via canary or AI | Treat canaries/alerts as leads, preserve chain of custody, require human investigation and appeal | A canary can be removed or copied; correlation alone is not proof of guilt |
| Help selected candidates despite a valid signed paper | Independently appointed oversight, staff conflict checks, restricted remote/admin access, external evidence retention, secure complaints outside local staff hierarchy | Staff and devices may collude; cameras or centre signatures cannot prove absence of assistance |
| Change answers after submission or substitute a candidate | Private identity/session binding, explicit response finalization, independent submission receipts and correction history; mode-specific OMR custody | Compromised input devices may lie before capture; biometrics and signatures do not prove who entered the answers |
| Exclude candidates through capacity, mode or language assumptions | Audited usable seats by district/shift, accessible mocks, accommodation and travel planning, reviewed equivalent forms and normalization | National venue counts and annual registrations do not establish local readiness; technical integrity cannot validate assessment quality |

## Security invariants for the verifier

1. Bind every proof to one protocol version, institutionally authenticated session identifier and signer root, canonical manifest, named log origin, two named witness keys and 2-of-2 quorum, beacon chain identity, and exact future round. The shadow Ethereum analysis additionally binds the pinned chain and registry code. The auditor's pre-round attestation and every selected-item content opening must bind to that same manifest and item ID. Reject replay across sessions or networks.
2. Require both consistency witness cosignatures over **the same pre-seed checkpoint**, independently retained or published before the round under the charter's timing assumptions. Their signatures do not assert a one-freeze count. A separate monitor must sign a root-and-size-bound full-scan report, actively check for new leaves through seed, handoff, and start, and supply fresh status to the centre. The centre's start decision is **provisional**: a public `FROZEN_BEFORE_SEED: VERIFIED` result also requires the later witnessed complete scan through the declared audit cutoff. The public verifier independently fetches all leaves through each required checkpoint, recomputes the Merkle roots, validates event signatures, and counts authorized freezes. A second otherwise valid freeze for the official session must be `FAILED`, even when the log remains perfectly append-only and both witnesses cosign it. Missing leaves, missed live-monitor status, or absent timing evidence is `INCOMPLETE` for the relevant claim and pauses the mock when required by the charter. [C2SP checkpoints](https://c2sp.org/tlog-checkpoint@v1.1.0) bind log origin, tree size, and root rather than an external index; [RFC 9162](https://www.rfc-editor.org/rfc/rfc9162.html) distinguishes inclusion/consistency from content monitoring.
3. Reject missing signatures, invalid beacon proof, unknown algorithm version, changed input root, or impossible blueprint. Verify post-exam and final post-appeal witnessed checkpoints and complete leaves through the declared cutoffs to expose cancellations, attempted second freezes, grievance decisions, and appeal outcomes. A pre-seed Ethereum anchor covers only that earlier prefix. The shadow claim that it was **finalized before the seed** requires replayable historical finality evidence; a pre-round block inclusion plus finality observed later is insufficient, so absent proof is `INCOMPLETE`. [Ethereum's proof-of-stake documentation](https://ethereum.org/developers/docs/consensus-mechanisms/pos/) distinguishes inclusion from finality. The shadow result cannot rescue a failed operational result.
4. Recompute the draw from the *committed ordered inventory*. Canonicalize the actual paper package, verify its complete content and order against the selected openings, then compare its digest with private release receipts and the later public commitment opening. Report draw reproduction, paper match, bank-auditor attestation, and delivery attestation as separate claims. If the inventory is undisclosed, report `AUDITOR_ATTESTED`, never `PUBLICLY_REPRODUCED`.
5. Record cancellation and emergency release as explicit terminal/exception states. Show every cancelled attempt and its replacement link, including any attempt after the seed was known. Never turn a failed verification into a green pass through a manual override.
6. Publish the synthetic mock's complete proof while its procedural-integrity challenge window still permits a remedy. For a reused secret bank, route the restricted bundle to an independent reviewer before the relevant deadline and publish a reviewable redacted finding; if neither route is available, report the candidate-actionability condition as unmet rather than treating a late public bundle as a remedy.
7. For the sealed profile, bind attestation, key-release policy, approval quorum, plaintext recipient, and authenticated release interval to the same manifest and current session epoch. Test every bypass including root/key-policy changes and restore. A software simulation cannot mark hardware isolation as verified. Preserve a negative-control case where full-bank knowledge defeats release secrecy while the integrity proof passes.
8. Keep paper custody, supervision, identity and response custody separate. A correct paper delivered to a dishonest centre may pass the first and fail or leave the others unproved. Do not infer guilt from an anomaly or infer national compromise from an isolated case.

## Review before live use

An independent security reviewer must inspect the formal protocol and implementation, bank-access design, beacon assumptions, key custody, centre hardware/software, backup paths, privacy handling, and incident process. A mock must deliberately simulate a malicious bank curator, a second otherwise valid pre-seed freeze with consistent witness signatures, equivocal log, absent witness, compromised centre, lost custodian, delayed disclosure, and beacon outage; the research-only Ethereum comparison also tests pre-round inclusion with post-round finality, a late anchor, and loss of designated witness archives. Any wrongly `VERIFIED` injection stops progression. The review findings and residual risks must be accepted by the accountable exam operator before any live-secret trial.
