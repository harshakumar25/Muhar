# Muhar one-centre mock: charter for review

**Draft, 9 November 2026 · unsigned · no institutional partner.** This is a proposed agreement for a voluntary, low-stakes computer-based mock using synthetic or retired questions. It is not an NTA policy, procurement requirement, legal notice, or authorization to handle live exam secrets. The named operator must fill and authenticate the fields below **before** the session is announced. A candidate representative and independent reviewer should challenge the terms before anyone is invited.

Iteration 3 adds the [sealed-paper experiment](../SEALED_PAPER_ARCHITECTURE.md) and [proposal acceptance gates](../PROPOSAL.md). A software-only simulation can test workflow; it cannot pass a hardware confidentiality claim. A second synthetic exam profile and two simulated endpoints test configuration reuse and early-to-late-centre leakage before any broader deployment claim.

## Decision this mock is meant to inform

Can a candidate and an independent reviewer receive usable evidence in time to challenge a wrong paper, a changed freeze, or an unexplained cancellation? Can the operator answer that challenge under a published rule? The cryptographic result is limited to the **named log and checkpoint prefix**, the committed draw, and signed delivery claims. It cannot certify that no person leaked a question, that a centre screen showed the signed pixels, or that the bank was fair.

The [October 2026 parliamentary committee](https://www.pib.gov.in/PressReleseDetailm.aspx?PRID=2321420&lang=1&reg=1) recommends large question banks, late paper setting, independent oversight, a secure grievance channel, published response timelines, and consideration of candidate harm. These are recommendations to investigate with a willing operator, not adopted Muhar obligations. An [NTA-hosted draft CBT tender](https://nta.ac.in/Download/Tender/Tender_20260302181817.pdf) describes giving a bilingual question-paper soft copy one hour before the exam start (p. 17 of the PDF). That particular tender is a **design input**: its one-hour handoff is not a universal current rule for Indian exams.

The [C2SP witness protocol](https://c2sp.org/tlog-witness@main) describes witnesses checking a checkpoint against their prior checkpoint. A cosignature is **not a content audit**. For this small mock, the content monitor reads every log leaf through each required checkpoint, validates the log root and authorised event signatures, counts freezes for the official session, and signs a report containing the log origin, checkpoint size/root, session ID, count, and software version. It watches for new leaves through the seed, handoff, and start and sends a signed status to the centre; a missed status deadline pauses the mock. A later verifier repeats full scans through the post-exam and final post-appeal checkpoints. Exactly one freeze in the `T−24h` prefix is a **provisional start condition**; the final one-freeze claim requires exactly one through the declared later audit cutoff. Neither count proves that no secret document exists elsewhere. The witnesses' independent **pre-round retention/publication** and the monitor's recorded receipt are timing evidence whose trust assumptions must appear in the verifier report. A backdated event time alone is not timing evidence.

## Schedule: choose one profile before seeing a seed

Times below are **proposed mock targets**, relative to scheduled start `T`, not external exam rules. The operator must sign the selected operational profile, its maximum delivery latency, its late-entry and accessibility rules, and the remedy for a missed deadline before freeze. Rehearse the other profile under a **different rehearsal session ID**; never choose the better result after seeing two draws for one official session.

| Event | Near-start handoff schedule | One-hour handoff schedule |
| --- | --- | --- |
| Freeze, auditor attestation, two witness cosignatures, and first full-scan report | By `T−24h`; independently retained before the named future seed round | Same relative freeze target for its separate rehearsal ID |
| Monitor freshness gate | Signed status at handoff and again before start, within the charter's maximum age; pause on a missed update, log gap, or second freeze | Same rule at its earlier handoff and at start; the later final scan can overturn either provisional result |
| Candidate admission rule | Mock admission closes at `T−15m`; accessibility needs and any permitted late entry are declared in advance | Same proposed admission boundary, exposing the difference between handoff and admission; operator must decide if this is acceptable for any real use |
| Verified public seed and deterministic draw | Target `T−12m`, only after required pre-seed evidence is retained | Target `T−75m`, so the selected form can be prepared before `T−60m` handoff |
| First authorised plaintext release, package handoff and signed delivery receipt | Target by `T−5m`; the approved centre runtime can decrypt at this handoff. Stop if the verified package misses the signed maximum latency | Target by `T−60m`; the recipient can decrypt then. Record the longer interval of centre/vendor exposure |
| Candidate start | `T` after signed digest match and centre readiness; this is not a second cryptographic release gate | `T` after signed digest match and centre readiness; the recipient already obtained the form at handoff |

The `T−60m` handoff plus a public seed at `T−75m` creates a 60-minute selected-form exposure **before this proposed admission close**, and 75 minutes before start. That is a **risk to measure**, not a security gain. The near-start option compresses the release window but is operationally harder and, with this mock's `T−15m` admission close, does not implement the committee's suggested late-entry approach. For live use, an operator must settle late entry, accommodations, human final-form review, and any form-equating plan with assessment specialists; the mock cannot make a universal policy for them. The whole selected paper may be known at the seed to anyone who can read the full bank under either profile.

The first profile releases directly to an approved recipient at handoff. It does not claim that this recipient remains unable to read the package until `T`. Prepositioning ciphertext and delivering a later key is a separate deferred protocol. Freeze primary and any backup recipient keys in the manifest; adding a new recipient key after freeze requires cancellation and a linked new session in v0. Activating an already frozen backup still needs an exact signed release permit and recorded incident.

## Candidate evidence and a usable challenge

1. **Receipt at exit.** Each volunteer receives the official session ID, form ID, language/accessible variant, full package digest, signed centre receipt reference, and an accessible paper or similarly independent retained copy. A QR is optional. Candidate identity and response data stay out of the public log.
2. **Secure procedural-integrity case type.** The willing operator must explicitly accept a no-fee **Muhar mock process challenge** through a named secure online or physical channel. This is separate from any existing answer-key challenge. It accepts a receipt, claimed screen mismatch, late release, cancellation, missing proof, or duplicate freeze; it returns a durable case ID and time-stamped acknowledgement. A participant may lodge a preservation notice immediately after the exam, even before proof publication.
3. **Disclosure gate.** Because this mock uses synthetic/retired items, publish the complete permitted proof bundle, full log leaves through a **two-witness post-exam checkpoint**, the monitor's root-and-size-bound report, signatures, draw transcript, package opening, and readable verifier instructions by `T+24h` as a proposed target. The procedural challenge window closes **no earlier than seven calendar days after complete usable disclosure**. A missing or unusable bundle extends the window; a late publication cannot silently consume it. After every case and appeal is resolved or formally closed, publish a **final two-witness checkpoint and full scan** through that declared cutoff, including redacted outcomes. Until then, the post-exam report is a current-prefix result, not a certificate of all future grievance history.
4. **Response and appeal.** Propose acknowledgement within one calendar day; a reasoned response with the exact evidence/claim status within five working days of a complete case; five working days to appeal to a different independent reviewer; and a reasoned appeal decision within five working days. The operator must prepublish contact, accessibility support, public incident-status updates, and how delays are signed and communicated. These deadlines are mock proposals for a willing partner to accept or revise before invitation.
5. **Remedy.** For this voluntary mock, available remedies are correction of the public record, independent re-verification, a documented retest/void decision, and a redacted incident report. There is no admissions or employment result to restore. The operator must name its real-world remedy and compensation authority separately before any consequential pilot.

If a later pilot reuses confidential questions and cannot publish the complete bank in time, an **independent, conflict-disclosed reviewer** must receive the restricted inventory and selected openings by the same action deadline, record its scope and finding, and allow a candidate to contest it through the signed case route. Publicly disclose redacted evidence as soon as safe. Until full disclosure, label selection `AUDITOR_ATTESTED` or `INCOMPLETE` as appropriate, not `DRAW_REPRODUCED` for the public. If neither timely public proof nor timely independent confidential review exists, do not claim the proof gives candidates a practical remedy. A later full public replay may still support retrospective accountability.

## Incidents, privacy, and stop rules

- **Release failure:** a wrong or unsigned package, missing witness, incomplete log, invalid beacon signature, bad monitor report, or wrong round pauses the mock. The operator logs a signed incident; no administrator override changes a failed proof to verified. A replacement uses a new linked session ID under the prepublished cancellation quorum.
- **Post-seed cancellation:** require signatures of the operator **and** independent case reviewer for the mock, a public reason stripped of private data, a link to every abandoned attempt, and after-action review. Do not run parallel precommitted forms and select one after seeing the seed.
- **Centre and candidate drills:** test power and link loss, wrong variant, local CBT reshuffle, accessible receipt delivery, late arrival, a preserved candidate complaint, and a simulated compromised centre. A centre signature is a claim of receipt, not proof of what pixels appeared.
- **Secrecy and collusion drills:** attempt unauthorized preview/export with one declared privileged role, one missing release approval, wrong worker/recipient, stale epoch, restored state, key-policy bypass and secret-bearing logs. Give a negative-control tester the full synthetic bank and public seed while release stays closed. Separately simulate valid delivery followed by prohibited assistance or altered responses; report custody and supervision/response evidence separately.
- **Evidence custody:** keep public synthetic proof bundles mirrored; keep candidate case files, seat/device mappings, raw centre logs, and any identifying evidence in a restricted encrypted vault with access logs. Propose retention until **90 days after final mock appeal closure**, with a documented hold while an incident is unresolved, then documented deletion subject to the adopting operator's actual legal obligations. Do not put identities, responses, biometrics, question text, answer keys, or grievance narratives on Ethereum.
- **Evaluation stops:** stop progression if any injected duplicate freeze, swapped package, split log, wrong round, or missing leaves is incorrectly reported `VERIFIED`, or a late anchor is incorrectly reported as a verified **shadow** result; if two independent verifiers cannot replay the synthetic draw; if the operator will not accept and answer the procedural case type; or if evidence will arrive only after the remedy deadline without a timely independent review route. A no-fee mock complaint that receives no response is a failed governance test even when the hash checks pass.

Record draw-to-package and seed-to-admission intervals, measured handoff latency and outages, proof publication delay, verifier agreement, candidate comprehension and accessibility feedback, case acknowledgement/decision time, and observed incident handling. Neither a clean mock nor an Ethereum transaction measures national leak reduction. Make the research-only Ethereum result a separate report with cost, finality evidence, archive-loss fault results, and the incremental detection it actually provided.
